# EdVyro Careers — Responsive Internship Board & REST API

An accessible, responsive web application and persistent **Express.js + SQLite** REST API built for **EdVyro Careers** to discover, filter, manage, and apply for student internships.

> **Milestone 3: REST API and Persistent Data**
> - **Backend**: Node.js + Express.js replaces the plain HTTP server.
> - **Persistent Database**: SQLite powered by `better-sqlite3` with strict parameterized queries.
> - **Schema Foundation**: Built upon `db/internship-board-sample.sql` and extended with complete schema migrations.
> - **Data Integrity**: Exact seed preservation of IDs `INT-101` through `INT-105` from `data/internships.json` with idempotent upsert seeding.
> - **Contract Envelope**: Predictable `{ status, data, pagination?, message?, errors? }` structure on all endpoints.
> - **Privacy & Security**: Zero-leak request logging (method, path, status code, duration only), parameterized queries, strict schema validation, and sanitized 500 error envelopes with zero stack trace exposure.

## Prerequisites & Quick Setup

### Prerequisites
- **Node.js**: v18.0.0 or higher (compatible with Node.js 18, 20, 22, and 24)
- **npm**: v9.0.0 or higher

### 1. Clone & Navigate to Project
```bash
git clone https://github.com/your-username/edvyro-careers.git
cd edvyro-careers
```

### 2. Install Dependencies
```bash
npm install
```

### 3. Configure Environment Variables
```bash
cp .env.example .env
```

### 4. Initialize Database Schema & Seed Data
```bash
npm run db:init
npm run db:seed
```

### 5. Launch the Server
```bash
npm start
```
The application will start at **`http://localhost:3000`**. Open this URL in any browser to interact with the responsive frontend.

## Environment Configuration (.env)

The application uses `dotenv` to load environment variables from `.env`. A complete template is provided in `.env.example`:

```ini
# Server Network Configuration
PORT=3000
NODE_ENV=development

# SQLite Database Storage Location
DB_PATH=./data/internships.db
```

| Variable | Default Value | Description |
| :--- | :--- | :--- |
| `PORT` | `3000` | Port on which the Express server listens. |
| `DB_PATH` | `./data/internships.db` | Filesystem path to the SQLite database file. Can also be `:memory:` for isolated testing. |
| `NODE_ENV` | `development` | Runtime environment (`development`, `test`, `production`). |

> **Security Rule**: The `.env` file and all `*.db` database files are strictly ignored in `.gitignore` to prevent leaking local configuration or storage artifacts into version control.

## Database Commands & Workflow

The project provides dedicated npm scripts for database operations:

| Command | Script | Description |
| :--- | :--- | :--- |
| `npm run db:init` | `node db/init.js` | Executes `db/internship-board-sample.sql` as the foundational schema, creates `internships` and `applications` tables, and applies schema extensions (adding `location`, `skills`, `openings`, `stipend`, `duration`, `description`, `portfolio_url`, `why_you`). |
| `npm run db:seed` | `node db/seed.js` | Reads `data/internships.json` and idempotently upserts `INT-101` through `INT-105` into the `internships` table using `ON CONFLICT(id) DO UPDATE SET`. Safe to run multiple times. |
| `npm start` | `node server.js` | Ensures database schema and initial data are ready, then starts the Express application. |
| `npm test` | `node --test test/server.test.js` | Runs the automated test suite testing all endpoints, pagination, search, validation, and status codes. |

## Database Schema & Data Model

The schema is built directly on top of `db/internship-board-sample.sql` and extended for complete Milestone 3 support.

```
┌──────────────────────────────────────────────┐
│                 internships                  │
├──────────────────────────────────────────────┤
│ id                 TEXT PRIMARY KEY          │
│ title              TEXT NOT NULL             │
│ domain             TEXT NOT NULL             │
│ mode               TEXT NOT NULL             │
│ location           TEXT DEFAULT 'Remote'     │
│ skills             TEXT DEFAULT '[]' (JSON)  │
│ openings           INTEGER DEFAULT 1         │
│ stipend            TEXT                      │
│ duration           TEXT                      │
│ description        TEXT                      │
│ duration_weeks     INTEGER NOT NULL          │
│ applications_open  INTEGER NOT NULL DEFAULT 1│
└──────────────────────────────────────────────┘
                       ▲
                       │ 1:N (Foreign Key)
┌──────────────────────────────────────────────┐
│                 applications                 │
├──────────────────────────────────────────────┤
│ id                 INTEGER PRIMARY KEY AUTO  │
│ internship_id      TEXT NOT NULL (FK)        │
│ applicant_name     TEXT NOT NULL             │
│ applicant_email    TEXT NOT NULL             │
│ portfolio_url      TEXT                      │
│ why_you            TEXT                      │
│ created_at         TEXT NOT NULL (TIMESTAMP) │
│ UNIQUE (internship_id, applicant_email)      │
└──────────────────────────────────────────────┘
```

### Table: `internships`
Stores available internship listings:
- `id` (`TEXT PRIMARY KEY`): Unique identifier (e.g., `INT-101`).
- `title` (`TEXT NOT NULL`): Role title.
- `domain` (`TEXT NOT NULL`): Industry domain (e.g., `Full Stack Development`, `UI/UX`, `Data Analytics`, `Cyber Security`).
- `mode` (`TEXT NOT NULL`): Work mode (`Remote`, `Hybrid`, `On-site`).
- `location` (`TEXT`): Geographical hub (e.g., `India`, `Pune`, `Bengaluru`).
- `skills` (`TEXT`): JSON string array of required skills (e.g., `["HTML", "CSS", "JavaScript"]`).
- `openings` (`INTEGER NOT NULL DEFAULT 1`): Open positions (integer >= 0).
- `stipend` (`TEXT`): Monthly stipend description (e.g., `₹25,000 / month`).
- `duration` (`TEXT`): Internship tenure (e.g., `6 Months`).
- `description` (`TEXT`): Detailed job responsibilities and learning objectives.
- `duration_weeks` (`INTEGER NOT NULL`): Duration normalized in weeks.
- `applications_open` (`INTEGER NOT NULL DEFAULT 1`): Flag indicating if applications are open (`1` = yes, `0` = closed).

### Table: `applications`
Stores candidate submissions:
- `id` (`INTEGER PRIMARY KEY AUTOINCREMENT`): Auto-incrementing primary key.
- `internship_id` (`TEXT NOT NULL`): References `internships(id)`.
- `applicant_name` (`TEXT NOT NULL`): Full legal candidate name.
- `applicant_email` (`TEXT NOT NULL`): Candidate contact email.
- `portfolio_url` (`TEXT`): Optional candidate portfolio / GitHub profile URL.
- `why_you` (`TEXT`): Candidate motivation statement.
- `created_at` (`TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP`): Submission timestamp.
- **Unique Constraint**: `UNIQUE (internship_id, applicant_email)` guarantees that a candidate cannot submit duplicate applications for the same role.

## API Response Envelope Contract

Every response generated by the API conforms strictly to a predictable JSON envelope:

```json
{
  "status": "success",
  "data": { ... },
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 9,
    "totalPages": 1
  },
  "message": "Human-readable summary of operation outcome.",
  "errors": [
    { "field": "fieldName", "message": "Field-specific validation error." }
  ]
}
```

### Standard Status Codes
| HTTP Status | Semantics | Scenario |
| :--- | :--- | :--- |
| **`200 OK`** | Success | Successful `GET`, `PUT`, or `DELETE` request. |
| **`201 Created`** | Created | Successful `POST` creating an internship or submitting an application. |
| **`400 Bad Request`** | Validation Error | Missing/invalid fields, unknown body keys, invalid JSON body. Returns field-level `errors`. |
| **`404 Not Found`** | Resource Missing | Non-existent internship ID or unknown API route. |
| **`409 Conflict`** | Duplicate | Candidate attempting duplicate application (same email + same internship). |
| **`500 Server Error`** | Server Error | Generic error message (`"Internal server error"`). Stack traces are never exposed. |

## API Reference & curl Examples

### 1. GET `/api/internships`
Returns a paginated list of internships with optional search and multi-filter parameters.

#### Query Parameters:
- `search` *(string, optional)*: Matches case-insensitively against `title`, `domain`, `location`, `skills`, or `description`.
- `domain` *(string, optional)*: Filters by specific domain (e.g. `UI/UX`, `Data Analytics`).
- `mode` *(string, optional)*: Filters by work mode (`Remote`, `Hybrid`, `On-site`).
- `page` *(integer, optional, default: 1)*: Current page number.
- `limit` *(integer, optional, default: 10, max: 50)*: Number of items per page. Capped strictly at 50.

#### curl: List with Pagination
```bash
curl -X GET "http://localhost:3000/api/internships?page=1&limit=2" \
  -H "Accept: application/json"
```

#### Sample Response (200 OK):

```json
    "duration": "6 Months",
```

### 6. POST `/api/applications`
Submits a student application. Validates candidate full name, email address, safe portfolio URL (`http`/`https` only), and valid internship ID. Prevents duplicate applications with `409 Conflict`.

#### curl: Success (201 Created)
```bash
curl -X POST "http://localhost:3000/api/applications" \
  -H "Content-Type: application/json" \
  -d '{
    "internshipId": "INT-101",
    "fullName": "Aarav Mehta",
    "email": "aarav.mehta@university.edu",
    "portfolioUrl": "https://github.com/aaravmehta",
    "whyYou": "Demonstrated hands-on experience building accessible React and modern CSS design systems."
  }'
```

#### Sample Response (201 Created):
```json
{
  "status": "success",
  "data": {
    "id": 1,
    "applicationId": "APP-1",
    "internshipId": "INT-101",
```

## Design & Security Considerations

### 1. SQL Injection Prevention
All database queries in `routes/internships.js`, `routes/applications.js`, and `db/database.js` are executed strictly using **parameterized statements** (`db.prepare('... ? ...').run(...)`). Dynamic filters build safe parameter arrays with `?` placeholders; string concatenation is strictly prohibited.

### 2. Privacy-Preserving Logging
The logging middleware intercepts every request and records:
- Timestamp: ISO 8601 string
- HTTP Method: `GET`, `POST`, `PUT`, `DELETE`
- Pathname: `req.originalUrl`
- Status Code: `res.statusCode`
- Duration: elapsed time in milliseconds

**Logs strictly exclude**:
- Request headers and authorization tokens
- Request bodies
- Applicant names, emails, and personal statements

Example log output:
```
[2026-11-19T12:53:02.246Z] GET /api/internships 200 - 7ms
[2026-11-19T12:53:02.345Z] POST /api/internships 400 - 1ms
[2026-11-19T12:53:02.394Z] POST /api/applications 201 - 1ms
[2026-11-19T12:53:02.400Z] POST /api/applications 409 - 2ms
```

### 3. Server Error Sanitization
In production and development, unhandled runtime errors return a generic `500 Internal Server Error` message:
```json
{
  "status": "error",
  "data": null,
  "message": "Internal server error"
}
```
Stack traces, file paths, and database internal error codes are suppressed from client responses.

### 4. Malformed JSON Body Protection
Express body parsing syntax errors are trapped by the error-handling middleware before reaching route handlers, responding immediately with `400 Bad Request` and field-level diagnosis.

### 5. Idempotent Migrations
Running `npm run db:seed` repeatedly uses SQLite's `INSERT ... ON CONFLICT(id) DO UPDATE SET` mechanism. This ensures that repeated runs or deployment scripts update existing rows rather than failing with constraint errors or creating duplicate records.

## Frontend Integration

The existing vanilla JavaScript frontend in `public/` communicates directly with the Express REST API:
- `fetchInternships()` calls `GET /api/internships?search=...&domain=...&mode=...&page=...&limit=...` and updates cards and pagination count.
- `openDetailsDialog(id)` calls `GET /api/internships/:id` and populates the accessible `<dialog>` modal.
- `submitApplicationApi(payload)` calls `POST /api/applications` with `{ internshipId, fullName, email, portfolioUrl, whyYou }`.
- Accessible DOM manipulation relies entirely on `textContent` and `createElement`—never `innerHTML`—preventing cross-site scripting (XSS).
